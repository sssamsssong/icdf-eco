# 시연 화면

`controller/main.py --gui`가 작은 웹 서버(`controller/server.py`)를 띄우고 이 페이지를 엽니다.
페이지는 0.25초마다 `/state`를 읽어 다시 그립니다. 인터넷 없이 동작합니다 (외부 글꼴·라이브러리 안 씀).
부스 모니터 1920x1080, 브라우저 F11 전체 화면 기준입니다.

| 주소 | 화면 |
|---|---|
| http://127.0.0.1:8000/ | 새 화면 (`index.html`): 우리 기술이 어떻게 판단하는지 보여 줌 |
| http://127.0.0.1:8000/classic | 예전 화면 (`classic.html`): 문제가 생기면 이걸로 |

## 새 화면 구성

- **①~⑤ 단계 줄**: 하루 전 예측 → 하루 전 계획 → 실행·관측 → ④ 오차 지속 예측 → ⑤ 이득-비용 판단.
  ④⑤는 "우리 기술" 표시. 오차가 크면 ④가, 작업을 옮기면 ⑤가 주황으로 빛남
- **탄소 그래프**: 하루 전 예측(점선)과 평균 오차 띠, 실제 값(흰 선), 구름(붉은 띠),
  **D2가 다시 본 남은 하루**(주황 선, ④의 예측을 반영한 갱신 예측), 최근 판단 화살표(지금 → 옮길 후보 시간, 옮김/유지)
- **④ 이 오차는 얼마나 이어질까?**: 왼쪽 막대 = 최근 4시간 실제 오차(모델 입력), 오른쪽 주황 선 = 학습 모델이 예측한 16시간 오차.
  점선은 "지금 오차 그대로", 가운데 0선은 B의 관점. 범례에 각 방법의 평균 오차(MAE)
- **⑤ 옮길까, 말까?**: 가장 최근 판단 하나를 크게. 지금 돌릴 때와 미룰 때의 예상 탄소, 이득 계산식, 이득 막대와 λ 선. 아래에 최근 판단 3개
- **작업 일정**: 두 랙의 48칸 x 2줄. D2가 옮긴 칸은 주황 테두리
- **아래 줄**: B·D2 누적 탄소와 팬, Jetson 실측 W, **실제 데이터로 검증** (장기 시뮬레이션 685일 결과, `sim/results/summary_test_default.csv`를 엔진이 읽어서 보냄)

## 설명할 때 주의

- 학습 모델은 구름이 짧을지 길지 **미리 알지 못합니다.** 처음 몇 칸은 오차가 이어진다고 봅니다.
  D2가 옮기는 기준은 "오차가 앞으로 줄어들어 나중 시간이 더 깨끗해 보이고, 그 이득이 λ보다 큰가"입니다.
- 부스의 구름은 계단 모양이라 D1(지금 오차에만 반응)에 유리합니다. 화면에 다른 전략을 실시간으로 띄우지 않고, 비교는 장기 시뮬레이션 표로 합니다.
- 학습 결과 숫자(MAE 등)는 `controller/config.py`의 `MODEL_FACTS`에 있습니다. 모델을 다시 학습하면 고치세요.

화면만 고칠 때는 엔진을 다시 켤 필요 없이 브라우저 새로고침만 하면 됩니다.
