# 시연 화면

`controller/main.py --gui`가 작은 웹 서버(`controller/server.py`)를 띄우고 이 페이지를 엽니다.
페이지는 0.25초마다 `/state`를 읽어 다시 그립니다. 인터넷 없이 동작합니다 (외부 글꼴·라이브러리 안 씀).
부스 모니터 1920x1080, 브라우저 F11 전체 화면 기준입니다.

| 주소 | 화면 | 켜는 법 |
|---|---|---|
| http://127.0.0.1:8000/ | 기본 화면 (`index.html`): 큰 그래프 + 두 랙 일정 + 결과 + 판단 3단계 | `icdf` |
| http://127.0.0.1:8000/detail | 자세한 화면 (`detail.html`): ①~⑤ 단계, 오차 그래프 축, 이득 계산식, 685일 검증 표 | `icdf --detail` |
| http://127.0.0.1:8000/classic | 예전 화면 (`classic.html`) | `icdf --classic` |

화면에서는 두 랙을 **Google**(하루 전 계획 고정, 코드·문서의 B)과 **YAX**(우리 방식, 코드·문서의 D2)로 부릅니다.
"Google"은 구글이 발표한 방식을 우리가 구현한 기준선이라는 뜻입니다. 구글의 실제 시스템을 돌리는 것이 아닙니다.

**Reactive**(문서의 D1)는 세 번째 줄입니다. YAX에서 학습 모델만 뺀 방식으로, 지금 오차에만 반응합니다.
팬과 Jetson 없이 화면에서만 같은 조건으로 계산합니다. **시연에서는 끄기로 했습니다** (`controller/config.py`의 `GUI_SHOW_REACTIVE = False`). `True`로 바꾸면 세 줄로 보입니다.
발표에서의 비교는 `docs/발표_추가슬라이드_설명.md`를 보세요.
부스의 계단 모양 구름에서는 Reactive가 YAX보다 탄소가 적게 나오는 장면이 많습니다. 실제 685일 데이터에서는 반대이고, 그 결과가 화면 맨 아래 한 줄에 있습니다.

## 기본 화면 구성

- **왼쪽 (한 장의 그림, 같은 시간축)**
  - 위: 하루 전 예측(점선), 실제(흰 선), 구름(붉은 띠), **AI가 다시 본 예측**(주황 선)
  - 아래: Google과 YAX의 작업 일정. 실행한 칸은 그때 전기가 깨끗했는지에 따라 초록/노랑/빨강.
    구름 속에서 Google은 빨간 칸으로 돌리고, YAX는 비워 두고(점선) 화살표로 나중 시간에 옮김
- **오른쪽 위**: 누적 탄소 두 숫자, 구름 속에서 실행한 칸 수, 차이
- **오른쪽 아래 (YAX는 이렇게 판단합니다)**: 1 예측이 얼마나 틀렸나 → 2 학습한 AI 모델이 오차가 계속될지 예측(작은 그래프) → 3 줄어드는 탄소 > 변경 비용이면 미룸
- **맨 아래 한 줄**: 685일 실제 데이터 검증 결과 (`sim/results/summary_test_default.csv`)

## 설명할 때 주의

- 학습 모델은 구름이 짧을지 길지 **미리 알지 못합니다.** 처음 몇 칸은 오차가 이어진다고 봅니다.
  D2가 옮기는 기준은 "오차가 앞으로 줄어들어 나중 시간이 더 깨끗해 보이고, 그 이득이 λ보다 큰가"입니다.
- 부스의 구름은 계단 모양이라 D1(지금 오차에만 반응)에 유리합니다. 화면에 다른 전략을 실시간으로 띄우지 않고, 비교는 장기 시뮬레이션 표로 합니다.
- 학습 결과 숫자(MAE 등)는 `controller/config.py`의 `MODEL_FACTS`에 있습니다. 모델을 다시 학습하면 고치세요.

화면만 고칠 때는 엔진을 다시 켤 필요 없이 브라우저 새로고침만 하면 됩니다.
