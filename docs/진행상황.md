# 진행 상황 (2026-11-19 기준)

전시: 2026 Energy ICDF, 11월 20일. 연세대 YAX.

## 하드웨어

- 랙 2개에 팬 4개 (B 랙 D3·D5, D2 랙 D6·D11). 4핀 Y 케이블은 4핀 쪽만 쓰고 3핀 가지는 잘라서 절연.
- 12V 전원과 GND는 5구 레버 커넥터 3개로 묶음. 배선도: `팬_LED_배선도_레버3개.png`
- 탄소 LED 바(WS2812)는 D7, 330Ω 저항과 1000µF 콘덴서 달고 5V 어댑터로 따로 전원.
- 팬이 LOW에서 안 꺼지던 문제 해결. 아두이노로 켜고 끄기 확인함.
- 아직: 새 펌웨어(`firmware/fan_led`)를 올려서 시연 엔진과 같이 돌려 보기.

## 발표·제출 자료 (저장소 밖 ICDF_eco 폴더)

- 발표 슬라이드 9장과 대본
- 부스판 v3 (CMYK 인쇄용)
- 작품 크기 제출 (약 100 × 50 × 60 cm)
- 배선도, 시스템 흐름도, 부스 예상도

## 장기 시뮬레이션 결과 요약

2025-01-01 ~ 2026-11-16, 람다 2 (2024년 데이터로 고름).

- D2는 하루 평균 2.4번 계획을 바꿔서, 예측이 틀려 놓친 탄소의 9.6%를 되찾음.
- 매번 다시 계획하는 방식(C)은 4.1번 바꿔서 8.9%. D2가 절반만 바꾸고 비슷하거나 더 많이 회복.
- 지금 오차만 보고 바꾸는 방식(D1)은 5.7번 바꾸고 2.3%. 람다가 작으면 오히려 손해.
- 다만 B 대비 절대 감소는 0.5% 정도로 작음. 보정이 작업을 뒤로 미루기만 하는 것도 한계.

자세한 표와 그래프: `sim/README.md`

## 남은 일

1. 새 펌웨어 올리고 `--gui --port COMx`로 팬·LED·화면이 같이 움직이는지 확인
2. 리허설: 날짜, 구름 길이, 람다 정하기. 짧은 구름이면 유지, 긴 구름이면 D2만 미루는 장면이 2분 안에 보여야 함
3. 발표 8장에 장기 시뮬레이션 결과를 넣을지 결정 (넣으면 "공개 데이터 시뮬레이션"과 한계를 같이 말하기)
4. 구름 입력은 키보드/화면 버튼으로 할지 센서로 할지 결정
5. Jetson 실측: 두 보드가 같은 작업에 늘어나는 전력이 달라(B +0.7 W, D2 +2.8 W) 화면에는 실측 W만 보여 줌 (`GUI_SHOW_MEASURED_CO2 = False`). 발표에서 실측값을 비교 근거로 쓰지 않기
6. 전시 후: Jetson 작업을 GPU(PyTorch)로, 두 보드 소프트웨어 맞추기, 앞당기기 보정, 작업 큐 현실화
