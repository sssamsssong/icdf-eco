# 탄소 인지 AI 데이터센터 스케줄러 (ICDF_eco)

2026 Energy ICDF 아이디어 2 · 초안 (2026-10-13)

## 한 줄 요약
유연한 AI 작업을 전력망이 깨끗한 시간대로 옮기는 계획을 **하루 전에 세우고**, 당일에는 예측 오차가 **계속 이어질 것 같을 때만** 계획을 고친다.

## 왜 하나
- 같은 1kWh라도 쓰는 시간에 따라 탄소 배출이 다르다. 마감 안에서 미룰 수 있는 작업(모델 학습, 배치 처리)은 깨끗한 시간대로 옮기면 배출이 줄어든다.
- 이 방식은 구글(2020~), 마이크로소프트, 학계에서 이미 검증됐다. 그래서 작업을 시간대로 옮기는 것 자체는 우리 기여가 아니다.
- 구글은 하루 전에 계획을 한 번 세우고 그대로 실행한다. 당일 예측이 틀려도 계획을 고치지 않고, 논문에서도 효과가 예측 정확도에 좌우된다고 인정한다.
- 반대로 매 순간 다시 계획하면 일정이 계속 바뀌어 운영이 불안정해진다.
- **우리 방식:** 하루 전 계획은 유지한다. 당일에는 오차가 얼마나 이어질지 단기 예측하고, 작업을 옮겨서 얻는 이득이 변경 비용보다 클 때만 고친다.

## 연구 질문
예측이 틀렸을 때 계획 변경을 최소한으로 하면서 오차로 생긴 탄소 손실을 얼마나 회복할 수 있는가? 단, 긴급 작업과 마감은 반드시 지킨다.

## 시스템 흐름
| 단계 | 하는 일 | 출력 |
|---|---|---|
| ① 하루 전 예측 (D-1) | 우리 모델로 다음 24시간 탄소 집약도 예측 | 예측 곡선 + 오차 범위 |
| ② 하루 전 계획 (D-1) | 유연한 작업을 예측상 저탄소 구간에 배치 | 작업별 실행 예정 시각 |
| ③ 실행 (D) | 실제 서버에서 작업 실행, 전력 측정 | 실행 기록, 실측 kWh |
| ④ 오차 감시 + 단기 예측 (D) | 실제와 예측의 차이 Δ를 보고, 그 오차가 얼마나 이어질지 추정해 남은 시간 예측을 갱신 | 갱신된 예측 + 불확실성 |
| ⑤ 이득-비용 보정 (D) | 예상 CO₂ 감소가 변경 비용보다 클 때만 변경 예산 안에서 수정, 긴급 작업은 고정 | 수정된 일정, 변경 이력 |

③~⑤는 매 시점 반복한다. 시연에서는 하루를 약 2분으로 배속한다(1시간 = 5초).

## 데이터
- **영국 NESO Carbon Intensity API**: 키 없이 사용 가능, CC BY 4.0
  - 전국 30분 단위 실제값, 2017년 9월부터 약 16만 개
- **시간순 분할**: 학습 ~2023 · 검증 2024 · 테스트 2025~
- **스케줄러가 받는 예측**: 우리 모델이 테스트 날에 대해 만든 예측. 오차가 자연스럽게 생긴다.
- **민감도 실험**: 실제값에 시간적으로 이어지는 합성 오차(0–30%)를 넣어 비교한다.
- **API의 과거 forecast 값**: 하루 전 예측이 아니라 직전 단기 예측으로 보인다. 그래서 `fw48h` 스냅샷을 지금부터 직접 수집해 현실적인 하루 전 오차를 확인한다.

## 비교 실험 (같은 작업 큐, 같은 마감)
- A. 즉시 실행: 기준선
- B. 하루 전 고정: 구글식
- C. 매 시점 재계획
- D1. Δ에만 반응하는 보정
- **D2. 단기 예측 + 이득-비용 보정 (우리 방식)**
- 완벽 예측: 이론상 상한

**지표**
- 에너지 kWh(실측)
- 추정 CO₂e
- 마감 준수율
- 평균 대기 시간
- 예측 오차(MAE)
- **계획 변경량**
- **오차 손실 회복률** = (B − D2) ÷ (B − 완벽 예측)

에너지와 탄소는 따로 보고한다. 작업을 옮겨도 전력량은 줄지 않고, 배출만 줄 수 있기 때문이다.

## 하드웨어 시연
- **메인 PC (마스터)**
  - 탄소 데이터를 배속 재생하고, 공통 시계와 탄소 신호를 두 Jetson에 똑같이 보낸다.
  - GUI를 띄우고, 모든 결정과 측정값을 CSV로 기록한다.
  - 장기 시뮬레이션 실험도 여기서 돌린다.
- **Jetson Orin Nano 2대 = 랙 2개**
  - #1은 B(구글식), #2는 D2(우리 방식)를 맡는다.
  - 하드웨어와 작업 큐가 같고, 스케줄러만 다르다.
  - 실제 AI 작업을 GPU로 돌리고, 내장 전력 센서로 랙별 전력을 따로 실측한다.
- **랙별 표시**
  - PCA9685와 MOSFET으로 팬 2개를 돌린다. 팬 하나가 작업 슬롯 하나이고, 냉각 장치가 아니다.
  - 서보로 누적 CO₂ 게이지를 움직인다.
- **태양·구름 스테이션 (1개, 공통 입력)**
  - 고정 램프 아래에 모형 패널과 조도센서를 둔다.
  - 구름 판을 올리면 탄소 신호에 +Δ가 더해진다. 반투명 판은 얇은 구름, 불투명 판은 두꺼운 구름이다.
  - 홀 센서를 백업으로 둔다.
- **소형 MCU**: 조도센서를 읽고, 두 랙 사이의 탄소 LED 바(WS2812)를 구동한다. PC와는 USB로 연결한다.
- **시연 장면**
  - 구름이 잠깐이면 D2는 계획을 유지한다.
  - 구름이 오래 머물면 D2만 유연한 작업을 멈추고, 구름이 걷히면 몰아서 처리한다.
- **RFID 작업 카드**(선택): 심사위원이 긴급/유연 작업을 직접 넣는다.

## 한계 (발표 때 밝힐 것)
- 영국 전력망 데이터 기반이다. 한국에서의 효과는 별도로 검증해야 한다.
- 영국 actual 값도 사후 추정치다.

- 아직 구현 전이다. 수치는 측정 후에만 쓴다.
